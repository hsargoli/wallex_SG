# گزارش نسخه دوم صفحه سفارش‌ها (Orders UI v2)

**تاریخ (میلادی):** 2026-10-04
**تاریخ (شمسی):** 1405/07/13
**وضعیت:** کامل

---

## هدف

بهبود صفحه `/orders` برای نمایش بهتر سفارشات، مخصوصاً **Stop-Limit** ها که قبلاً دیده نمی‌شدند.

---

## کشف کلیدی

با DevTools مرورگر کشف شد که Wallex **دو endpoint جداگانه** داره:

| Endpoint | کاربرد |
|---|---|
| `GET /v1/account/orders` | تاریخچه سفارشات (۲۵ سفارش) |
| `GET /v1/account/openOrders` | سفارشات باز فعلی (۱۲ سفارش) |

**سفارشات STOP_LIMIT فقط تو `openOrders` هستن.**

### ساختار STOP_LIMIT

```json
{
  "symbol": "LINKTMN",
  "type": "STOP_LIMIT",
  "side": "BUY",
  "price": "3650000",
  "stopPrice": "3654329",
  "stopPriceCondition": "<=",
  "origQty": "1.36",
  "status": "NEW",
  "active": true
}

نکته: فیلد stopPriceCondition جدید بود که قبلاً پشتیبانی نمی‌کردیم.
تغییرات Backend
۱. client.py

    اضافه کردن get_open_orders() → /v1/account/openOrders

۲. mapper.py

    اضافه کردن stop_price_condition به map_order

    Helper جدید _iso_to_ts() برای تبدیل ISO 8601 → Unix timestamp

        قبل: created_at همیشه ۰ بود

        بعد: 2026-10-03T20:13:41Z → 1791058421

۳. order.py (entity)

    اضافه کردن stop_price و stop_price_condition

۴. orders.py (router)

    Endpoint جدید: GET /v1/orders/open

    Endpoint موجود GET /v1/orders حالا status filter می‌گیره

۵. schemas.py

    OrderResponse حالا stop_price و stop_price_condition داره

تغییرات Frontend
۱. api.ts

    Type جدید stop_price_condition

    متد جدید listOpenOrders

۲. queries.ts

    Hook جدید useOpenOrders با auto-refresh ۱۰ ثانیه

۳. orders/page.tsx

    ۵ کارت آمار: توقف | باز | پر شده | لغو | مجموع

    ۵ بخش گروه‌بندی:

        🛑 سفارشات توقف (Stop-Limit)

        ⏱ سفارشات باز (Limit)

        🕐 آخرین سفارشات من

        ✅ تکمیل شده

        🚫 لغو / رد شده

    همه بخش‌ها بسته به‌طور پیش‌فرض (کاربر خودش باز می‌کنه)

    نمایش باکس نارنجی برای STOP ها با قیمت توقف و شرط

    Border نارنجی برای کارت‌های STOP

آمار نهایی

درس‌های آموخته

۱. DevTools مرورگر بهترین راه کشف endpointهای مخفی است. مستندات والکس ناقصه.

۲. ISO 8601 vs Unix timestamp — Wallex created_at رو string میده، نه integer.

۳. Wallex صفحه‌بندی رو نادیده می‌گیره — limit و page کار نمی‌کنن.

۴. stopPriceCondition فیلد مهمی است — برای STOP_LIMIT ها < یا <= یا > یا >=.

    افزودن قابلیت ثبت STOP_LIMIT از UI

    نوتیفیکیشن وقتی STOP فعال میشه

    بهبود صفحه /bots (بعدی)
