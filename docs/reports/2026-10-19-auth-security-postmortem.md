# 🩺 Post-Mortem: Auth & Security (Sprint 2)

**تاریخ:** 2026-10-19
**نویسنده:** دی فردوس
**وضعیت:** حل شد (Resolved)

## 🎯 هدف (Context)
پیاده‌سازی سیستم امنیتی شامل فراموشی رمز عبور (با ایمیل)، تغییر رمز، و زیرساخت تایید ایمیل به همراه محدودیت نرخ (Rate Limit) روی لاگین.

## 🏗️ معماری پیاده‌سازی شده
- **دیتابیس:** جدول `auth_tokens` برای ذخیره توکن‌های هش‌شده (SHA-256) با انقضا. اضافه شدن فیلد `is_verified` به `User`.
- **ایمیل:** استفاده از الگوی Hexagonal (Port/Adapter). در محیط لوکال از `MockEmailSender` (چاپ در ترمینال) استفاده شد.
- **امنیت:** محدودیت ۵ درخواست در دقیقه برای لاگین و ۳ درخواست برای فراموشی رمز با استفاده از `SlowAPI`.

## 🐛 چالش‌ها (The Bugs)
1. **خطای ۵۰۰ در API فراموشی رمز:** با وجود اینکه منطق سرویس کار می‌کرد، فراخوانی از طریق Endpoint منجر به خطای ۵۰۰ می‌شد.
   - **ریشه‌یابی:** کتابخانه `SlowAPI` برای تزریق هدرهای Rate Limit به پارامتر `response: Response` در امضای Endpoint نیاز دارد. فقدان این پارامتر باعث کرش می‌شد.
   - **راه‌حل:** اضافه کردن پارامتر `response` به توابع محدودشده.
2. **خطای بیلد در پروداکشن (خطای ۴۰۴):** بیلد فرانت‌اند روی سرور به دلیل استفاده اشتباه از `className` در کامپوننت `SarvLogo` با شکست مواجه شد.
   - **راه‌حل:** اصلاح پراپ‌ها به `size` و **تست بیلد لوکال (`npm run build`) قبل از دیپلوی**. (درس بزرگ: هرگز بدون بیلد لوکال، بیلد پروداکشن نگیرید).

## ✅ نتیجه
- کاربر می‌تواند با ایمیل، لینک بازیابی دریافت کند.
- رمز عبور در دیتابیس به صورت امن تغییر می‌کند.
- تمامی مسیرها روی پروداکشن (`sarvbots.ir`) تست و تایید شدند.
