# گزارش افزودن صفحه سفارش‌ها (Orders UI)

**تاریخ (میلادی):** 2026-10-04
**تاریخ (شمسی):** 1405/07/13
**وضعیت:** کامل

---

## هدف

افزودن صفحه‌ای برای دیدن و مدیریت سفارش‌های واقعی روی صرافی والکس.

## کارهای انجام‌شده

### ۱. Backend

- رفع باگ slowapi: افزودن پارامتر `response: Response` به endpointهای `orders.py`
  - علت: `headers_enabled=True` در Limiter
  - خطا: `parameter response must be instance of Response`

### ۲. Frontend — API Client

افزودن به `lib/api.ts`:

- Types جدید: `Order`, `OrderSide`, `TradingOrderType`, `OrderStatus`, `OrdersListResponse`, `PlaceOrderRequest`
- متدهای جدید: `listOrders`, `placeOrder`, `cancelOrder`

**توجه:** تغییر نام `OrderType` جدید به `TradingOrderType` برای جلوگیری از تعارض با `OrderType = "maker" | "taker"` قدیمی (profitability).

### ۳. Frontend — React Query Hooks

افزودن به `lib/queries.ts`:

- `useOrders` — لیست با auto-refresh هر ۱۰ ثانیه
- `usePlaceOrder` — mutation با toast و نقشه‌برداری خطاها
- `useCancelOrder` — mutation با تأیید

### ۴. Frontend — صفحه /orders

ساخت `app/orders/page.tsx`:

- لیست سفارش‌ها با badge رنگی (خرید/فروش، وضعیت)
- فیلتر بر اساس نماد
- دیالوگ ثبت سفارش (BUY/SELL، LIMIT/MARKET)
- دکمه لغو برای سفارش‌های فعال
- پیش‌نمایش مبلغ کل در دیالوگ
- هشدار قبل از ثبت

### ۵. Sidebar

افزودن آیتم «سفارش‌ها» با آیکون `ClipboardList`.

## درس‌های آموخته

۱. **slowapi نیاز به Response parameter داره** — اگه endpointها `response: Response` نگیرن، خطا می‌ده.

۲. **تعارض نام‌ها در TypeScript** — `OrderType` قدیمی (profitability) با جدید (trading) قاطی می‌شد. حل: تغییر نام جدید به `TradingOrderType`.

۳. **`--reload` ممکنه چند ثانیه طول بکشه** — تست‌های بلافاصله بعد تغییر، ممکنه خطا بدن.

## قدم‌های بعدی

- بهبود صفحه `/bots` برای دیدن فعالیت ربات‌ها
- فعال کردن `LIVE_TRADING_ENABLED` برای تست کامل
- اضافه کردن نمودار سفارش‌ها
