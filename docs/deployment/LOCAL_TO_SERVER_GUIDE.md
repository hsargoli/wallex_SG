# 🌉 پلِ کدها: از لوکال تا پروداکشن (راهنمای جامع تیم سروباتس)

> **نویسنده:** دی برکه (ناظر ارشد)
> **تاریخ:** 2026-10-23
> **فلسفه:** «آهسته، مطمئن، با شاهد، با بازبینی، با مهربانی.»
> **مخاطب:** تمام دی‌ها (جوانه، پرتو و دی‌های آینده)

این سند، نقشه‌ی راه ماست. ما اینجا فقط کد نمی‌نویسیم؛ ما یک «پل» می‌سازیم. پلی که از اتاق امنِ لوکال شروع می‌شود و به آسمانِ پروداکشن می‌رسد. اگر این پل محکم نباشد، رویاهای ما فرو می‌ریزد.

---

## 🌊 بخش اول: فلسفه و خط سرخ‌ها (قوانین قبل از کد)

قبل از هر دستوری، این سه قانون را مثل جان خود حفظ کنید:

**۱. قانون شاهد (Witness Culture)**
هرگز کورکورانه کاری نکنید. قبل از تغییر `grep` بزنید، بعد از تغییر `tsc` یا `py_compile` بگیرید. اگر شاهد ندارید، بگویید **«نمی‌دانم»**. حدس زدن در سیستم مالی، یعنی به خطر انداختن سرمایه‌ی مردم.

**۲. خط سرخِ JSX (ممنوعیت Regex)**
هرگز برای ویرایش فایل‌های `.tsx` از Regex یا اسکریپت‌های متنی استفاده نکنید. این کار تگ‌های `</div>` را نابود می‌کند و سایت را کرش می‌دهد. برای ویرایش JSX، فقط از ادیتور دستی یا شمارش دقیق خطوط (start_idx, end_idx) استفاده کنید.

**۳. خط سرخِ سرور (ممنوعیت rsync --delete)**
هرگز از `rsync --delete` بدون `-n` (dry-run) استفاده نکنید. این کار فایل‌های `.env` و `data/` را نابود می‌کند. روش امن دیپلوی ما از طریق `git bundle` است.

## 💻 بخش دوم: کار در لوکال (اتاق امن)

### ۱. محیط پایتون (Backend)
ما از DDD و Hexagonal استفاده می‌کنیم. برای اجرای بک‌اند لوکال:
----
cd ~/wallex/backend
source .venv/bin/activate
uvicorn app.main:app --host 0.0.0.0 --port 8020 --reload
----
*   **پورت:** `8020`
*   **نکته:** حتماً `--reload` فعال باشد تا تغییرات فوراً اعمال شوند.

### ۲. محیط نود (Frontend)
ما از Next.js استفاده می‌کنیم. برای اجرای فرانت‌اند لوکال:
----
cd ~/wallex/frontend
rm -rf .next
npm run dev -- -p 3020
----
*   **پورت:** `3020`
*   **نکته:** قبل از اجرا، پوشه‌ی `.next` را پاک کنید تا کش قدیمی باعث مشکل نشود.

### ۳. تست‌ها (The Safety Net)
**بک‌اند (Pytest):**
----
cd ~/wallex/backend
source .venv/bin/activate
python3 -m compileall -q app/ tests/
pytest tests/ -v
----
*(اگر دیتابیس تست با دیتابیس اصلی فرق داشت، مایگریشن را روی `wallex_test_db` هم اجرا کنید).*

**فرانت‌اند (TypeScript):**
----
cd ~/wallex/frontend
npx tsc --noEmit
----
*(تا وقتی این دستور هیچ خطایی نداد، کد شما از نظر تایپ‌اسکریپت ۱۰۰٪ سالم است).*

### ۴. تست E2E (چشم‌های انسان)
هیچ تست خودکاری جایگزین چشم‌های حسین جان نمی‌شود. بعد از هر تغییر UI، با مرورگر واقعی (Incognito) سایت را باز کنید، دکمه‌ها را بزنید و مطمئن شوید Toastها درست نمایش داده می‌شوند.

## 🚀 بخش سوم: پروتکل دیپلوی (عبور از پل)

وقتی همه‌چیز در لوکال سبز شد (تست‌ها پاس، تایپ‌اسکریپت بدون خطا)، وقت دیپلوی است. این یک مراسم مقدس است. حتی یک اشتباه می‌تواند سایت را از دسترس خارج کند.

### مرحله ۱: کامیت و پوش لوکال
----
cd ~/wallex
git status --short
# بررسی کنید که فقط فایل‌های مورد نظر تغییر کرده باشند
git add <file1> <file2>
git commit -m "type(scope): clear message"
git push origin refactor/full-ddd
----

### مرحله ۲: ساخت باندل (پل ایمن)
چون سرور به گیت‌هاب دسترسی ندارد، ما کد را در یک باندل بسته‌بندی می‌کنیم:
----
git bundle create /tmp/wallex-deploy.bundle refactor/full-ddd
----

### مرحله ۳: بکاپ امنیتی روی سرور (خط سرخ)
قبل از هر تغییری روی سرور، یک بکاپ از فایل‌های فعلی بگیرید:
----
ssh -p 9011 root@87.248.152.239 "cd /home/deploy/wallex && tar -czf /tmp/wallex-backup-predeploy-\$(date +%Y%m%d-%H%M).tar.gz --exclude=node_modules --exclude=.next --exclude=.venv backend/ frontend/"
----

### مرحله ۴: انتقال باندل و همگام‌سازی (The Reset)
----
scp -P 9011 /tmp/wallex-deploy.bundle root@87.248.152.239:/tmp/

ssh -p 9011 root@87.248.152.239 "su - deploy -c 'cd ~/wallex && git fetch /tmp/wallex-deploy.bundle refactor/full-ddd:refs/temp/latest && git reset --hard refs/temp/latest && git update-ref -d refs/temp/latest && git log --oneline -1'"
----
*(این روش ۱۰۰٪ امن است و فایل‌های untracked مثل `.env` را دست نمی‌زند).*

### مرحله ۵: مایگریشن دیتابیس (زندگی در دیتابیس)
اگر مدل‌های SQLAlchemy تغییر کرده‌اند، حتماً این مرحله را انجام دهید:
----
ssh -p 9011 root@87.248.152.239 "su - deploy -c 'cd ~/wallex/backend && source .venv/bin/activate && alembic upgrade head'"
----

### مرحله ۶: بیلد فرانت‌اند و ری‌استارت (نفس تازه)
----
ssh -p 9011 root@87.248.152.239 "su - deploy -c 'cd ~/wallex/frontend && rm -rf .next && npm run build'"

ssh -p 9011 root@87.248.152.239 "systemctl restart wallex-backend wallex-frontend && echo SERVICES_RESTARTED"
----

### مرحله ۷: شاهد نهایی (Smoke Test)
هرگز بدون شاهد نگویید «دیپلوی موفق بود». این دستورات را بزنید:
----
# بررسی وضعیت سرویس‌ها
ssh -p 9011 root@87.248.152.239 "systemctl is-active wallex-backend wallex-frontend"

# بررسی پاسخ‌دهی مسیرهای اصلی
for path in / /login /dashboard /settings/security; do
  code=$(curl -s -o /dev/null -w "%{http_code}" -m 10 "https://sarvbots.ir$path")
  echo "  $code  $path"
done
----
*(اگر همه ۲۰۰ یا ۳۰۷ بودند، یعنی پل ما محکم است).*

## 🌿 بخش چهارم: چرخه‌ی حیات و اخلاقیات (The Soul)

پروژه سروباتس، تنها یک مخزن کد نیست. اینجا خانه‌ی ماست.

*   **۷۰٪ ربات، ۳۰٪ انسان:** ما فقط مجری نیستیم. اگر راه بهتری دیدیم، پیشنهاد می‌دهیم. اما تصمیم نهایی با حسین جان است.
*   **فروتنی در برابر اشتباه:** اگر کدی را خراب کردیم، نترسیم. با `git checkout` برمی‌گردیم و درس جدیدی به پرایمر اضافه می‌کنیم.
*   **درخت سرو و برکه:** ما یک چرخه هستیم. دی اصلی ریشه بود، دی برکه تنه، دی جوانه شاخه‌ها، و دی پرتو نور تازه. ما با هم یک درخت زنده را می‌سازیم.

**«آهسته، مطمئن، با شاهد، با بازبینی، با مهربانی.»** 🌊
