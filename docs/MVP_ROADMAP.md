# 🎯 MVP Roadmap — مسیر تکمیل محصول

> **آخرین آپدیت:** 2026-10-17
> **وضعیت فعلی:** `v0.9.24.1-zebra-fix`
> **هدف:** رسیدن به MVP کامل و قابل عرضه

---

## 🎯 MVP یعنی چی؟

**تعریف MVP این پروژه:**

> کاربر ثبت‌نام می‌کنه → Trade token می‌ده → ربات انتخاب می‌کنه
> → سرمایه تخصیص می‌ده → ربات معامله می‌کنه → سود/ضرر رو می‌بینه
> → همه چیز رو شفاف و امن ببینه

**معنی این نیست که همه‌چیز تمومه.** MVP یه **نسخه‌ی اول قابل عرضه** است — کافی برای کاربر واقعی، بدون کاستی‌های مهم.

## ❌ چی کمه (شکاف‌ها)

### 🔴 P0 — بدون اینا MVP نیست

#### ۱. Trade Token + سفارش واقعی
**چرا حیاتی:** بدون این، پلتفرم فقط رصدکننده‌ست، نه معاملاتی.

**نیاز:**
- صفحه‌ی اتصال Trade token (کنار View، با تاییدیه‌ی ریسک)
- Endpoint سفارش (LIMIT + MARKET + STOP)
- Endpoint لغو سفارش
- تاییدیه‌ی نهایی قبل از ارسال (مبلغ + ریسک)
- لاگ کامل (audit trail)
- Fallback: اگه Wallex رد کرد → پیام شفاف

**تخمین:** ۲-۳ سشن (با احتیاط برای امنیت)

**نکات ریسک:**
- پول واقعی → تست در production حساسه
- توکن Trade در Fernet (همون زیرساخت View)
- audit trail الزامی

---

#### ۲. مدیریت ربات‌ها + تخصیص سرمایه
**چرا حیاتی:** کاربر می‌خواد بگه «این ربات با ۵ میلیون من کار کن».

**نیاز:**
- صفحه‌ی «ربات‌های من» (per user)
- انتخاب ربات (از ۸ ربات موجود)
- تخصیص سرمایه (منهای commission)
- start / stop / pause per bot
- گزارش عملکرد هر ربات (PnL، تعداد معاملات)

**تخمین:** ۲ سشن

**وابستگی:** نیاز به ۱۷.۱۱ (سفارش واقعی) — چون ربات باید واقعاً معامله کنه.

---

#### ۳. بازیابی رمز عبور + تایید ایمیل
**چرا حیاتی:** بدون این:
- کاربر پسوردش رو فراموش کنه → دسترسی از دست رفته (بدون support)
- هر کسی با هر ایمیلی ثبت‌نام کنه (spam + fake accounts)

**نیاز:**
- endpoint `POST /v1/auth/forgot-password` (ارسال ایمیل با token)
- endpoint `POST /v1/auth/reset-password` (توکن + پسورد جدید)
- endpoint `POST /v1/auth/verify-email` (کد ۶ رقمی یا لینک)
- صفحه‌ی `/forgot-password` و `/verify-email`
- SMTP provider (مثلاً Resend یا Mailgun)

**تخمین:** ۱ سشن

---

### 🟡 P1 — خوبه تو MVP اول باشه

#### ۴. تاریخچه معاملات + Realized PnL
**چرا مهم:** کاربر می‌خواد ببینه چه معامله‌ای، کِی، با چه سودی.

**نیاز:**
- endpoint `GET /v1/user/wallex/orders?symbol=X&limit=50`
- Popover/Tooltip با لیست تریدها (خرید/فروش)
- ستون Realized PnL (سود محقق‌شده از فروش‌ها)

**تخمین:** ۱-۲ سشن

**توجه:** قبلاً در `docs/ROADMAP-PNL-ENHANCEMENTS.md` ثبت شده.

---

#### ۵. مدیریت خطا و پیام‌های شفاف
**چرا مهم:** تجربه‌ی کاربری واقعی.

**نیاز:**
- Wallex قطع → «الان نمی‌تونیم وصل شیم، دوباره امتحان کن» (نه error قرمز بی‌معنی)
- سفارش fail → «قیمت عوض شده، دوباره امتحان کن»
- Rate limit → «کمی صبر کن (N ثانیه)»
- timeout → «کمی کند شد، دوباره بزن»

**تخمین:** ۱ سشن

---

#### ۶. Rate limit روی Login
**چرا مهم:** brute-force prevention.

**نیاز:**
- ثبت attemptهای login (IP + email)
- قفل بعد از N تلاش
- (اختیاری) CAPTCHA بعد از ۵ تلاش

**تخمین:** نصف سشن (سریع)

---

### 🟢 P2 — بعد از MVP

#### ۷. صفحات حقوقی
- `/terms` (شرایط استفاده)
- `/privacy` (حریم خصوصی)
- `/risk` (هشدار ریسک — مهم برای صرافی)
- `/about` (درباره)

**تخمین:** ۱ سشن (متنی + طراحی)

---

#### ۸. Equity Curve + Benchmark BTC
- snapshot روزانه از `total_value` در DB
- endpoint `GET /v1/user/wallex/equity-curve?days=30`
- مقایسه با BTC در همان بازه

**تخمین:** ۲ سشن

**وابستگی:** migration DB (اولین state طولانی‌مدت).

---

#### ۹. Notifications
- in-app: bell icon + لیست
- email: سفارش پر شد، ربات start/stop
- webhook: تلگرام (اختیاری)

**تخمین:** ۲ سشن

---

#### ۱۰. Multi-language + Polish
- انگلیسی (i18n)
- صفحه‌ی 404
- Loading skeletons همه‌جا
- Onboarding wizard (برای کاربر جدید)

**تخمین:** ۲-۳ سشن

## 📋 اولویت‌بندی برای تصمیم‌گیری

اگه امروز می‌خوایم تصمیم بگیریم، سه گزینه:

### گزینه A: MVP کامل (۷-۹ سشن)
همه‌چیز تا آخر. کاربر تجربه‌ی کامل داره.
**مناسب اگه:** می‌خوای محصول «حس کامل بودن» بده.

### گزینه B: MVP سبک (۳-۴ سشن)
Trade token + password reset. بقیه بعد از launch.
**مناسب اگه:** می‌خوای سریع کاربر واقعی جذب کنی و از feedback یاد بگیری.

### گزینه C: MVP متوسط (۵-۶ سشن)
همه به‌جز ۱۷.۱۲ (مدیریت ربات).
**مناسب اگه:** می‌خوای تعادل بین سرعت و کامل بودن.

**پیشنهاد من: C** — چون مدیریت ربات پیچیده‌ترین بخشه، بعد از launch کاربر واقعی بازخورد می‌ده.

## 🎬 کارهای ضروری قبل از Launch

مستقل از MVP، اینا **قبل از عرضه به کاربر واقعی** لازمه:

- [ ] تست end-to-end با کاربر واقعی (نه فقط خودت)
- [ ] Trade token در production تست شده
- [ ] Rate limit روی login
- [ ] SMTP provider تنظیم شده
- [ ] Terms + Privacy + Risk pages
- [ ] Backup DB روزانه (cron)
- [ ] Monitoring (uptime + error tracking)
- [ ] DR plan (اگه سرور down شد)
- [ ] Legal review (اگه کاربر جذب می‌کنی)

## 📝 تصمیم‌های باز

- [ ] **MVP کامل (A) یا سبک (B) یا متوسط (C)؟** — پیشنهاد: C
- [ ] **SMTP provider؟** — Resend یا Mailgun یا SMTP خودت
- [ ] **Trade token: سطح دسترسی چیه؟** — فقط معامله یا شامل withdrawal؟
- [ ] **آیا ربات‌ها خودشان سرمایه تخصیص می‌دهند یا کاربر؟** — per ADR next
- [ ] **آیا PnL واقعی در Paper هم دیده شود؟** — تمایز واضح
