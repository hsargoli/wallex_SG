# ADR-0042 — SarvRouter Conversation Engine (MVP Scope)

- **Status:** Proposed
- **Date:** 2026-11-09
- **Author:** دی دریا (CTO)
- **Reviewers:** حسین (رهبر), دی کویر (مسئول SarvRouter)
- **Related:** ADR-0039 (Copilot), ADR-0040 (Decision Contract)

---

## 1. Context

در فاز ۱ و ۲، Copilot بامعنا شد و ریسک را نشان داد.
فاز ۳ (گفتگو) قرار است به کاربر اجازه دهد بپرسد: «چرا این پیشنهاد را دادی؟»

**نسخه کامل (Full Version) این فاز شامل:**
- ذخیره تمام tickها در یک فایل `JSONL`.
- جستجوی تاریخی بر اساس `tick_id`.
- ادغام با LLM برای پاسخ‌های طبیعی.

**مشکل:** پیاده‌سازی نسخه کامل، زمان‌بر است و برای اعتبارسنجی ایده (MVP) نیازی به آن نیست. ما باید اول ثابت کنیم کاربران با این قابلیت تعامل می‌کنند.

## 2. Decision (MVP Scope)

برای MVP، فقط روی **آخرین تصمیم** تمرکز می‌کنیم و یک موتور پاسخ‌دهی ساده و سریع می‌سازیم.

### 2.1. محدوده MVP (In Scope)
- یک endpoint جدید: `GET /sarvrouter/why`
- موتور پاسخ‌دهی Rule-based (بدون LLM).
- خواندن از `state.last_decision` (که در فاز ۱ ساختیم).
- پاسخ شامل یک متن فارسی (برای UI) و `evidence` (برای شفافیت).

### 2.2. خارج از محدوده MVP (Out of Scope / Future)
- ذخیره تاریخی تصمیم‌ها (JSONL).
- پرسش درباره‌ی tickهای گذشته (بدون `tick_id`).
- پاسخ‌های زبانی تولیدشده توسط LLM.

### 2.3. موتور پاسخ‌دهی (Rule Engine)

یک کلاس `ConversationEngine` ساخته می‌شود که این قوانین را دارد:

| `last_decision.action` | متن پاسخ (why) |
|---|---|
| `pending` | «منتظر تثبیت روند هستم. رژیم فعلی X است، اما باید Y کندل دیگر پایدار بماند.» |
| `switched` | «روند به X تغییر کرد و پایدار ماند. ربات‌های مربوطه فعال شدند.» |
| `no_change` | «وضعیت تغییری نکرده است. استراتژی فعلی (X) به کار خود ادامه می‌دهد.» |
| `kill_switch_active` | «دستور توقف دستی فعال است. ورودهای جدید مسدود شده‌اند.» |
| `daily_loss_kill` | «حد ضرر روزانه (X٪) فعال شد. سیستم برای محافظت از سرمایه متوقف شد.» |

### 2.4. خروجی API

    GET /sarvrouter/why

    Response (200 OK):
    {
      "answer": "منتظر تثبیت روند هستم. رژیم فعلی صعودی است، اما باید ۱۲ کندل دیگر پایدار بماند.",
      "action": "pending",
      "evidence": { ... },
      "confidence": 0.8,
      "is_mvp": true
    }

- اگر هنوز هیچ تصمیمی ثبت نشده باشد، پاسخ `503 Service Unavailable` است.
- پاسخ متناظر با `last_decision.action` است.

## 3. Consequences

- **مزایا:** سریع پیاده‌سازی می‌شود. نیازی به دیتابیس جدید یا فایل JSONL ندارد. بلافاصله در UI قابل نمایش است.
- **معایب:** کاربر نمی‌تواند بپرسد «چرا ۳ ساعت پیش این تصمیم را گرفتی؟» (این به فاز ۳ کامل موکول می‌شود).
- **تغییرات کد:** `app/services/bots/sarv_router/conversation.py` (جدید)، `app/presentation/api/v1/sarvrouter.py` (اضافه شدن endpoint).

## 4. Open Questions

۱. آیا `answer` باید همیشه فارسی باشد یا بر اساس زبان کاربر؟
   - **تصمیم MVP:** فعلاً فقط فارسی.

۲. آیا باید در UI دکمه‌ای برای پرسیدن وجود داشته باشد؟
   - **تصمیم MVP:** بله، یک دکمه «چرا؟» زیر کارت آخرین تصمیم که این endpoint را صدا می‌زند.

## 5. Witness

پذیرش این ADR با سه شاهد:
- سه تست جدید برای `ConversationEngine`.
- یک تست برای endpoint `/why` (وقتی last_decision وجود ندارد → 503).
- یک تست برای endpoint `/why` (وقتی last_decision وجود دارد → 200 + پاسخ درست).
